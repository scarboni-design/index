When to use the toast

Confirm something just happened

"Exam exported." "Settings saved." The action is done — the toast just confirms it.

Share a status update

"All wires are properly connected." Info the user can see or ignore — doesn't stop what they're doing.

Report an error the user can retry

"Sync failed." They stay on the same screen and try again — no need to interrupt.

Give background feedback

"STAT exam pending review." Ambient awareness while eyes stay on the ECG trace.

Toast vs. pop-up

Toast

  • Nothing for the user to decide
  • Rest of the screen keeps working
  • Fits in one short line
  • OK if the user doesn't see it

Pop-up

  • User must choose an action ("Delete exam?")
  • Blocks the flow until resolved (password mismatch)
  • Needs more than one line, or has buttons
  • Must be seen and acknowledged

Rules for this component

  • -Only one toast at a time. A new one replaces the current one — never stacks.
  • -One line only — icon + short message, no title.
  • -Auto-dismiss after ~4.5s. No close button needed unless there's an action link.
  • -Position: bottom-center over full-screen content like the ECG trace.
  • -Color lives only in the icon — no colored border or fill.
